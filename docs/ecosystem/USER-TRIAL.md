# 真实任务与独立接入试用包（待开展）

状态 NOT_RUN，2026-10-05。可交给参与者的独立包已准备：outputs/研序v2_生态接入验收包.3，文件身份见 integration-kit-selected-context-v2.json。这里只保存执行准备，没有招募、发送邀请、捏造参与者或宣称用户收益。用户提供的 v2 提议先观察约 5–8 位目标用户、两个自然工作周期，是探索起点，非统计有效样本量。

## 目标和范围

首批个人独立负责长期产出、已使用 Agent、遇到上下文丢失/方案反复/外部变化影响旧决定。选择真实的产品迭代、开发项目或科研管理任务。每人明确选材料、项目、目录和发送范围；不用全盘扫描换取演示便利。每轮预算由参与者确认，当前开发验收的“额度不设限”不自动授权参与者账号或新任务。

## 三个可以独立结束的任务

1. 评审：参与者提出真实取舍问题，提供获准材料/约束；先单执行器，得到简报后直接阅读、维持原判断、人工修订或导出均可结束。记录实际时延、尝试/成功次数、引用是否支持论断、有用取舍、缺失依据、阅读负担和下一次是否主动使用。
2. 观察：参与者选关注问题和少量明确来源；检查有变化/无变化/无关变化/失败/过期。需要保留一次真实更新，静态成功不够。直接阅读或归档可结束；不强迫每条变化进入评审。记录实际应检查、已尝试、成功读取、缺口、被判有用提醒及被过滤样本的人工抽查。
3. 接续：自然中断后换会话或执行器，先读项目目标、旧判断、来源版本和下一步；记录恢复用时/操作、是否找错项目、是否重复已做工作。能打开记录不等于减少重复。

## 独立生态接入

选择一个没有参与核心代码开发的人，仅提供 OPEN-CONTRACT、示例来源包、review-client.py、获准项目令牌及测试任务。不得授予主人令牌或让其改数据库。

检查能否自行完成来源包导入或外部评审回复；能否解释覆盖和 UNKNOWN；无雷达也能导入选定材料，无评审 UI 也能由外部 Agent 完成获准请求；成果可被另一个工具读用。记录遇到的理解/兼容/授权问题和必要开发者协助。全由维护者自己操作不算独立接入通过。

## 记录表

| 字段 | 填写规则 |
|---|---|
| 任务/对象/版本 | 真实目标、参与者匿名 ID、项目/简报/source 版本 |
| 授权 | 所选材料、目录、账号、执行器、网络及预算范围 |
| 输出 | 成果文件或版本化引用，保留原回复/编辑/失败 |
| 工程状态 | PASS / FAIL / ONGOING / NOT_RUN / RESOURCE_BLOCKED |
| 内容质量 | 引用支持/不支持/未知；有用取舍/反例/缺失信息 |
| 产品结果 | 完成、合理不行动、继续执行、放弃及其原因 |
| 费用/负担 | 实际尝试、可观察费用、耗时；未知不能填零 |
| 复用 | 下一次任务是否主动选用、未使用原因 |
| 接续 | 原目标是否保持、负结果是否保留、重复工作 |

对单 Agent 与多角色做比较前，另行冻结相同问题/材料/格式与成本边界；尽量盲审来源。多角色若没有增加有用信息而增加成本/阅读负担，就保持高级选项；不按角色数或输出长度评分。

出现越权发送、恢复重复执行或旧结果覆盖新判断，应停止对应路径并保存失败。无实质变化不追加审计循环；没有新风险不重跑未受影响的整套测试。
