# 雷达与群聊推送

2026-10-05 当前源码能力 `radar.group_push.v1`。沿用公开来源读取、变化快照、收件箱、群对象及同一 SQLite；不新增云账号或另一套项目。

## 用户链路

雷达首页按“最新发现、关注来源、覆盖详情”显示。来源设置选择问题、公开 URL、关键词、频率，并选择目标收件箱或已有群。首次成功读取只建立基线；以后的文字差异匹配规则时创建发现，自动推送只建立待讨论项。群列表未读数、群内待讨论栏和应用内提醒提示送达。

“查看并讨论”先展示来源差异、问题、回复成员和历史范围；用户确认后才创建一轮群聊执行。每位所选成员最多回复一次，发送冻结差异、问题、选定历史和空间简介；任务/决策/结果选定集合为空。消息附来源卡片，能回看送达时的差异并返回原群。标记已查看清除未读但仍待讨论；忽略从待讨论栏移出，原记录保留。

## HTTP 契约

使用现有人类 `POST /api/ecosystem`，携带 project_id，先 dry:true 再版本匹配提交。无需新令牌。

- `watch.save`：既有 auto_push/push_target(personal|project)，新增 push_group_id（空值送到收件箱）。目标群必须属于对应讨论空间；非同项目/个人讨论空间拒绝。公开来源启用仍需 radar-public-source-v1。
- `alert.push`：target 为同项目或个人讨论空间，新增 group_id（可空），支持显式再次选择目标。每个 alert＋空间＋群组合幂等；既有普通收件箱编号保持不变。
- `group.send`：既有 id/expected_rev/content/reply_profile_ids/history_count/consent=group-chat-message-v1；讨论推送时再传 inbox_id、整数 inbox_expected_rev、source_version。必须属于当前群、未讨论/忽略且至少选择一位成员；来源、群成员及队列版本改变时拒绝。
- `GET /api/ecosystem`：群新增 pending_inbox（待讨论元数据）和 unread_count；详细来源仍从同空间 inbox 读取。旧客户端不使用新字段也能读取旧来源与收件箱。

确认提交在一个事务中绑定群消息、房间和收件箱，保存原始 source_change/source_version，状态改 discussed。重复确认不重新启动。Codex/外部 Agent 收到同一冻结 source_change；外部成员仍受原握手、角色、权限和回复契约限制。

备份校验新增目标群、消息来源和房间的双向关联。新实现继续读取旧备份；包含新群定向推送的备份应使用具备本能力的版本恢复，不能承诺旧 preview.8 可读取所有新字段。

## 失败与运行条件

来源读取失败不创建发现/推送，保留最近成功材料并显示覆盖缺口。目标群不可用时，发现和本次来源版本仍保存，delivery_error 提示手动重新选择目标；不静默重推。相同未变来源不重复推送。服务重启保留队列和消耗，不重放模型调用；自动检查需要本机核心运行，休眠/关闭会造成覆盖缺口。

本轮交付应用内提醒，没有系统桌面通知、邮件、微信外发或云端全天候推送。当前真实公开来源解析门禁仍阻塞；没有绕过 DNS/内网地址限制。

验证：radar-group-push-validation.json（历史本地记录）。合成软件链路 PASS，真实来源/模型质量/独立用户试用不能据此判定通过。
