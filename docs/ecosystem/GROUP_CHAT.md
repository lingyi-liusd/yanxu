# 持久群聊（2026-10-05）

用户本轮明确授权：聊天室参考微信群聊；允许用户自己创建群聊，把不同模型加入群中。此变更在 v2 项目、评审、观察之上增加群聊入口，沿用同一核心与空间身份。

## 使用

打开 `/?mode=chat` 或 `/apps/discussion/`，点击 ＋ 创建群聊，填写群名并选择已配置模型。最多 6 位模型成员；可以先建立空群，再通过详情中的“配置模型 / Agent”和“邀请 / 管理成员”补齐。配置支持共享 Codex 接口提供的模型和已登记的外部 Agent，不代表任意厂商 API 已接入。

左侧会话列表与搜索，中间用户绿色气泡 / 模型白色气泡，右侧成员与群信息。每条消息勾选回复者，选择带入最近 0、5、10、20 条群历史，再发送。未勾选仅保存人工文字；有勾选时每位成员最多回复一次。群名、成员、人工消息与模型回复本机持久保存，轮询和模式切换期间的草稿与回复选择保留在当前页面内存；刷新页面后未发送草稿不保留。

成员在回复期间禁止再次发送，可停止当前轮。改成员只影响后续消息，既有执行合同与消耗不改写。模型配置调整后需通过群设置保存成员，才更新群中的配置快照。历史上限 200 条人工消息、单条文字 4000 字、单次群历史 200KB；达到上限明确提示新建群或减少历史范围，旧记录保留。

## API 与通信

统一 `POST /api/ecosystem`，仍需本机用户授权令牌、`project_id`、`ifRev`；预览 `dry:true` 不提交或调用模型。`GET /api/ecosystem?project_id=…` 新增 `groups`，包含派生 `timeline`、`active_room_id`、累计 `used_calls`。

- `group.create`: `name`, `profile_ids`（可为空）。
- `group.update`: `id`, `expected_rev`, `name`, `profile_ids`。
- `group.send`: `id`, `expected_rev`, `content`, `reply_profile_ids`, `history_count`, `consent:group-chat-message-v1`。仅人工文字不用模型同意字段。

存储沿用 SQLite `ecosystem_items`，新增 `group` 类型。需要模型时每条消息创建独立单轮 `room`，冻结成员与 `group_source`（群版本、选定历史、哈希），继承原有停止、去重、权限和配额对账。没有勾选任务、决策、结果，不发送其他群或本地文件正文；发送范围包括当前空间简介、模型职责、本条问题与选定群历史。

Codex 走原有共享连接；外部 Agent 通过原 MCP/HTTP 领取请求，新增 `mode:group` 与 `group_source`，`previous_messages` 为选定历史，继续使用四字段 `project.reply_discussion`。旧客户端需正确处理新增模式和历史消息类型；尚未经过独立第三方接入验收。页面仍使用轮询读取，无新 WebSocket 服务或多租户云服务。
